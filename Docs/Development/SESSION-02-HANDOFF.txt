2. 완료한 규칙
보드와 좌표:
- Pointy-top odd-r, 논리 좌표는 row 0..6, col 0..행 길이-1.
- 짝수 행 6개, 홀수 행 5개: 6/5/6/5/6/5/6, 합계 39칸.
- GridShapeData 마스크와 실제 생성이 동일한 GetActiveOffsets를 사용. 예전 width+1 우회 행/마스크 밖 생성을 제거.
- 화면 중앙 배치는 논리 좌표를 음수로 옮기는 대신 실제 타일 경계 중심에 카메라를 배치하여 처리.
- 기존 HexCoordinates의 올바른 Cube 변환(q+r+s=0)을 공통 기반으로 사용. HexOffsetUtils의 잘못된 이웃 목록·양방향 OR 우회·BFS 거리를 제거하고 공통 Cube 계산에 위임.
- HexUtils 반경의 중심/상대좌표 혼용과 라인 보간의 조기 정수 반올림을 수정.
- TileMatcher 내부의 별도 Cube 구조를 제거. 폭발 반경과 수평/3축 라인은 공통 유틸리티를 사용. 아이템 효과 자체의 완성은 세션 05 범위로 유지.

화면과 선택:
- 실제 스프라이트 경계와 퍼즐 카메라 뷰포트의 가로·세로 비율에 맞추어 카메라 크기/중심 계산. 해상도가 바뀌면 LateUpdate에서 다시 맞춤.
- 화면→보드 평면의 Ray→실제 렌더 중심을 기준으로 선택. 기존 tileAnchor 수동 차감 + WorldToCell 우회 제거.
- 타일 앵커·위치·회전·비균일 배율을 반영. 퍼즐 뷰포트/화면 밖은 선택 불가.
- 마우스는 기본 육각 판정, 터치는 1.3배 판정 후보를 적용. 겹친 판정 영역은 가장 가까운 타일 중심을 선택.
- touchVerticalOffset 기본 0. 상단 보정은 화면 높이에 대한 비율로 조절 가능하며 실제 기기 확인 후 튜닝(D-001).

입력:
- 같은 색의 인접 타일 2개 이상을 연결한 뒤 Release에서 한 번 처리.
- 다른 색 타일 진입은 선택 전부 취소. 이 동작은 입력 잠금을 만들지 않음.
- 이미 선택한 타일로 돌아오면 해당 타일은 유지하고 뒤쪽 선택만 해제.
- 같은 색 비인접 타일로 건너뛰기는 추가하지 않음. 백엔드에서도 중복 셀/비활성/비인접/다른 색 체인을 거부.
- Release 최종 위치를 반영하고 처리 전에 선택 상태를 정리. 마우스와 Enhanced Touch가 같은 경로를 사용.
- 터치 취소(Canceled)는 매칭으로 제출하지 않음. 한 손가락을 추적하고 마우스가 연결되어 있어도 같은 터치를 이중 처리하지 않음.
- 외부 LockInput은 선택을 취소하고 잔여 시간을 갱신. 장애물 오답 판정 자체는 세션 03.
- UI 위에서 시작하는 입력과 플레이 상태가 아닌 입력은 차단. 아이템 단독 터치는 기존 미구현 상태를 유지하고 세션 05로 남김.

요구 색 보정:
- 등록된 요구 색의 인접 쌍을 일반 타일의 최소 재색칠로 확보.
- 아이템을 다른 색으로 바꾸지 않음. 선택 중/비활성/호출자가 보호한 셀을 건드리지 않음. 보정 불가이면 false를 반환하고 부분 변경하지 않음.
- 생성 완료 및 TileMatcher의 전체 제자리 리필 후 등록된 요구 색을 재검사.
- 마스크 밖 SpawnTile 요청은 null을 반환하고 보드를 늘리지 않음.

4. 데이터·API·이벤트 계약
GridShapeData:
- width는 짝수 행의 열 수, 홀수 행은 width-1.
- GetRowWidth(int row), IsTileActive(Vector3Int), GetActiveOffsets().
- 논리 셀의 z는 0. 음수 논리 셀은 기본 보드 마스크 밖이지만 공통 Cube 수학은 음수 좌표도 지원.
- 예전 보드의 음수 중심 오프셋을 복원하지 말 것. 현재 구형 SaveManager는 보드를 저장하지 않았으며 세션 06에서 새 저장 버전·마스크 검사를 적용해야 함.

HexOffsetUtils:
- GetNeighbors: 정확히 6개, 공통 HexCoordinates와 방향 인덱스 동일.
- IsAdjacent/GetDistance: 공통 Cube 거리 1/거리 계산. 양방향 우회 없음.
- GetRange(center, radius): 마스크와 무관한 공통 반경. 실제 영향은 보드의 활성 셀로 필터링.
- IsOnLine(center, cell, allAxes): false는 같은 r의 가로 한 줄, true는 q/r/s 중 한 축이 같은 세 방향.

PuzzleBoardManager:
- FitCameraToBoard(), GetBoardWorldBounds(): 실제 타일 경계로 맞춤.
- TryGetTileAtWorldPosition(world, hitAreaScale, out cell): 렌더 중심 기반 판정.
- SetRequiredMatchColor(TileColor?): 요구 색 등록/전환 후 즉시 재검사. null은 요구 색 해제(현재 색은 변경하지 않음).
- EnsureRequiredColorPair(ISet<Vector3Int> protectedCells = null): 등록된 요구 색 재검사.
- TryEnsureAdjacentPair(TileColor, ISet<Vector3Int> protectedCells = null): 요구 색 등록을 바꾸지 않고 특정 색 보정.
- bool 반환은 성공 여부. 초기화 전 또는 보호 조건으로 보정 불가하면 false를 처리해야 함. 초기화 전 등록된 요구 색은 생성 완료 후 재검사됨.
- 보호 셀 집합은 해당 호출에만 적용. 아이템·선택·비활성 타일 보호는 기본 적용.
- 장애물 요구 색/보스의 다음 요구 색 이벤트에서 SetRequiredMatchColor를 호출하는 연결은 세션 03/04에서 구현할 것. 이번에는 공용 기반과 리필 후 호출만 구현·검증.

TileInputHandler:
- TryGetTileAtScreenPosition(position, out cell, isTouch=false), SelectedChain/IsSelecting/IsInputLocked 읽기, 기존 LockInput(duration) 유지.
- 새 보정 필드는 Inspector 설정 가능. 실제 기기 상단 보정은 기본 0에서 조정.
- GameEvents의 기존 서명 변경 없음. 실제 매칭 완료는 기존 TileMatcher→ScoreManager→OnMatchCompleted 경로 유지.
- 입력/카메라 API의 검증은 실제 게임 프레임에서 수행해야 함. EditorApplication.update에서 UnityEngine.Screen을 읽으면 편집기/Scene View 크기와 혼동할 수 있음.
