2. 완료한 규칙
씬·상태:
- Game/Score/Stamina/Save/Boss 서비스는 씬 소유 SceneSingleton을 사용. Main에서 빈 서비스 자동 생성 안 함. 씬 파괴 시 참조 해제, 공유 루트의 중복은 컴포넌트만 제거. DataManager는 전역 데이터로 유지하고 중복 Awake 가드.
- Main↔Game 왕복 시 새 보드/현재 씬 참조/단일 EventSystem을 유지. 파괴된 이벤트 구독 정리.
- Briefing→Runner→Boss→Result 상태 흐름 정비. Boss 진입은 전체 장애물 성공 후 한 번만 발생. Result는 timeScale=0, 진행/자연 감소/퍼즐 처리 정지.
- Pause는 Runner/Boss 원래 상태를 저장하고 timeScale=0. Resume는 해당 상태로 복귀하며 타이머·보드·HP·진행·장애물 위치·성공 예약을 유지. 이동/재시작 시 timeScale 복원.
- 기존 씬을 유지하며 최소 PAUSE/RESUME/RESTART/HOME UI를 런타임 연결. 실제 입력 이벤트로 버튼 검사. 게임 상태 디버그 패널은 활성 플레이에서 제외하고 소스/씬 배치 보존.
- Restart는 보드·입력 잠금·선택·애니메이션·주행·가속·장애물·재도전 상태 초기화. Pause 시 진행 중 드래그 선택은 취소하지만 보드 색·아이템은 보존.
장애물:
- StageData의 빨강 점프→파랑 슬라이드→노랑 방어 3종 유지. 기본 길이 250/속도 5=기본 이동 50초(장애물 정지·재도전 시간과 가속은 별도). 장애물 속도 obstacleMoveSpeed=4.
- 2초 사전 경고와 실제 입력 구간을 구분. 입력 구간 내 같은 요구 색 2개 이상 매칭 완료 시 해당 장애물 인스턴스에 성공 예약. 애니메이션 종료와 무관하게 충돌 시 한 번 판정.
- 잘못된 완료 매칭은 0.5초 잠금. 다른 색 드래그로 선택 자체가 취소되는 세션 02 규칙과 구별. 예약 후 다른 매칭을 해도 예약 취소 안 함.
- 실패는 20 피해, 진행률 고정·자연 감소 유지, 2초 후 같은 인덱스의 새 장애물 재도전. 반복 실패·Pause 중 재도전 타이머 보존. 성공할 때만 장애물 완료 수 증가.
- 노랑 성공은 장애물 충돌 피해 0. 청록 무적 효과로 장애물 실패 피해를 우회하지 않음. 보라 가속은 BalanceData 1.5배/3초를 실제 주행 속도에 반영.
- 요구 색은 보드 SetRequiredMatchColor에 연결. 생성/색 전환/리필 후 일반 타일 인접 쌍 확보, 보정 불가 경고와 다음 리필 재검사. 아이템·선택 보호는 세션 02 계약 유지.
- 보스 내부 전투는 보존한 채 enableCombat=false 기본값으로 비활성. 세션 03은 BossPhase/진입 이벤트까지만 활성. 승리까지 완주한 것으로 해석하지 말 것.

4. 데이터·API·이벤트 계약
- SceneSingleton<T>.Instance: 씬에 있으면 반환, 없으면 null. 외부 전역 Singleton처럼 자동 생성/영구 루트화하지 않음. IsCreated/IsOwner 가드 후 이벤트 구독. 전역 DataManager는 외부 Singleton 유지.
- GameManager.StateBeforePause, IsResuming 읽기. Resume 시 IsResuming=true 상태에서 상태 이벤트를 동기 발행하므로 Boss 등은 새 전투 초기화를 건너뛸 것.
- GameEvents 기존 서명 유지. OnBossAppeared는 전 장애물 완료+StageLength 도달 후 한 번. GameStateChanged는 재개에도 Runner/Boss를 발행하므로 초기화는 Briefing에서만 수행.
- PuzzleBoardManager.IsInitialized, ResetBoard() 추가. ResetBoard는 TileAnimation.CancelAll 후 39칸 생성/카메라 맞춤. 기존 SetRequiredMatchColor/EnsureRequiredColorPair 계약 유지.
- RunnerProgressSystem.RunnerSpeed는 StageData.runnerSpeed × RunnerController.SpeedMultiplier. IsPaused는 장애물 진행 정지 플래그이며 게임 Pause와 별개. 재개 이벤트로 해제하지 말 것. NextStopDistance에서 프레임 초과 이동을 제한.
- RunnerController.ActionTimeRemaining/BoostTimeRemaining/SpeedMultiplier 읽기. 가속 잔여 시간은 Runner에서만 감소. 행동/가속 초기화는 Briefing/Result.
- ObstacleController.Initialize 기존 인수 뒤 TileColor? 선택 인수 추가. HasSuccessReservation/IsResolved/IsInitialized/RequiredColor/RequiredAction/DistanceToRunner/TimeUntilCollision/IsInputWindowOpen 읽기.
- Resolved(ObstacleController,bool), InputWindowOpened(ObstacleController)는 소유 spawner가 인스턴스로 구독/해제. 기존 static OnObstacleFailed/OnObstacleCleared는 Save/UI 호환용 유지. 사망/리셋 후 재도전 이벤트로 상태를 되살리지 않음.
- ObstacleSpawner.NextObstacleIndex/ClearedObstacleCount는 성공 완료 개수. 스폰할 때 증가하지 않음. 실패 재시도는 동일 인덱스. AllObstaclesCleared는 완료 수와 현재/재도전 부재를 함께 확인.
- CurrentObstacle/RetryRemaining/IsPreWarning/NextStopDistance/WarningRemaining 읽기. 경고 HUD는 실제 잔여 시간과 READY 표시.
- StageData.obstacleMoveSpeed 신규, 기본/현재 에셋 4. 기존 ID prototype-stage-01 및 Boss/Balance 참조 유지.
- BossController.enableCombat=false 기본. 세션 04는 1.1 전투 구현·검증 후 명시적으로 활성화해야 함. 보존된 패턴 코루틴은 scaled time 사용, Pause/Resume에서 재생성하지 않으며 OnDisable에서 이벤트 구독 취소.
- SaveManager는 씬 소유로만 변경. 저장 버전/손상 처리/원자 쓰기는 세션 06. 현재 NextObstacleIndex는 성공 경계이지만 구형 저장의 의미/마이그레이션까지 보장하지 않음. 사용자 원본 저장으로 시험하지 말 것.

8. 재현·복구 방법
- Unity 6000.3.14f1에서 다른 동일 프로젝트 Editor를 닫은 뒤 위 CLI 실행. CLI가 Editor를 시작하므로 사용자가 미리 켜둘 필요 없음. 그래픽 캡처 검사는 로그인된 macOS 화면 세션 필요.
- 수동: Main→Play→시작, 우측 PAUSE→RESUME/RESTART/HOME. Main 재진입 반복. 장애물 경고 후 실제 입력 구간에서 요구 색 2개 이상을 연결 완료. 실패 후 진행 고정·HP 감소·2초 재시도 관찰. 3종 성공 후 진행 끝에서 BossPhase.
- 사용자 저장이 있으면 기존 자동 복원 경로가 개입할 수 있음. 자동 검사는 이를 격리했으며 수동 검사는 원본 저장을 백업한 후 별도 프로필/복사본 사용. 구형 저장을 삭제하는 처리는 이번에 추가하지 않음.
- 수정 전 세션 02 복구 기준선은 로컬/원격 커밋 47a43f8358e43d35392b0f420057d4b27f1e85fc. 현재 작업에 덮어쓰지 말고 새 빈 폴더에 복원:
restore='/private/tmp/Nyan-Link-before-session03'
mkdir "$restore"
git archive 47a43f8358e43d35392b0f420057d4b27f1e85fc | tar -x -C "$restore"
- 캐시/Library는 재생성, Git 패키지는 SSH 인증 필요할 수 있음. 원본 Library 삭제·git reset/checkout으로 작업 덮어쓰기 금지.
- 세션 01 원래 사용자 미커밋·미추적 작업까지 포함한 외부 백업:
/Users/kiwoolee/.codex/visualizations/2026/11/13/01a1d285-d609-7523-a6ba-5ad5d5334841/Nyan-Link-session01-backup
복구 절차·해시/실제 복원 근거는 SESSION-01-HANDOFF.txt와 백업 restore-verification.txt.
- 현재 세션 03까지 보존하려면 별도 폴더에 Git diff와 untracked 파일/새 .meta를 함께 복사할 것. 이번 세션 작업은 아직 Git 커밋에 포함되지 않음.
