냥링크 웹 테스트 빌드·배포 안내
작성·최근 확인: 2026-11-16 (Asia/Seoul)
대상 주소: https://fairstudios.kr/nyan-link/

1. 전달물과 범위
- Builds/Web/nyan-link/ : 실제 업로드할 정적 파일 전체.
- Builds/Web/nyan-link-deploy.zip : nyan-link/ 폴더를 포함한 전달용 압축 파일.
- Builds/Web/nyan-link-deploy.zip.sha256 : 압축 파일 무결성 값.
- nyan-link/release.json : 파일별 SHA256·크기·목표 주소.
- 회사 서버 업로드/설정 변경 및 원격 저장소 push는 이번 준비 작업에 포함하지 않음.
  공개 사이트 응답만으로 호스팅 관리 계정/실제 문서 루트는 알 수 없음.

2. 웹 실행 방식
Unity 6000.3.14f1 WebGL Release, Main→Game 씬, 단일 스레드.
Gzip + Unity Decompression Fallback, 파일명 hash, 브라우저 저장 자동 동기화.
일반 HTTPS 정적 파일 호스팅으로 실행. 별도 게임 서버·DB·COOP/COEP 설정 불필요.
540px 이내 9:16 세로 화면, 기기 픽셀 비율 상한2, 다운로드 진행/오류 안내.
웹에서는 효과 없는 게임 종료 버튼을 숨김. 종료는 브라우저 탭 닫기.
게임 불러오기→게임 시작 클릭으로 진입. 사운드는 브라우저 사용자 입력 정책을 따름.

3. 회사 사이트에 게시
호스팅 관리자/배포 담당자가 현재 fairstudios.kr의 문서 루트와 업로드 방식을 확인.
압축을 풀면 나오는 nyan-link/ 폴더를 해당 문서 루트 아래에 배치.
결과 경로: <문서 루트>/nyan-link/index.html 및 Build/ 등.
nyan-link/nyan-link/로 중복 배치하지 말 것. legend-stone/과 루트 index는 변경하지 말 것.
HTTPS GET /nyan-link/ 와 모든 Build 파일이 로그인/리다이렉트/HTML 대체 없이 제공되어야 함.
SPA/WordPress 재작성 규칙이 있으면 실제 nyan-link 파일/디렉터리는 예외 처리.

서버별 설정:
- Apache: 동봉된 .htaccess가 JavaScript MIME과 캐시 정책을 제공.
  AllowOverride가 금지되어500이면 이 파일을 제외하고 서버 관리자에게 같은 정책 적용 요청.
- Nginx: .htaccess는 적용 안 됨. Tools/WebHosting/nginx.conf.example을 기존 HTTPS
  server 설정에 맞게 검토·반영. 문서 루트와 다른 서비스 설정은 유지.
- 기타 정적 호스팅: .js=application/javascript, .unityweb=application/octet-stream.
  .unityweb는 Unity가 직접 압축 해제하므로 Content-Encoding:gzip/br을 강제하지 말 것.
  업로드 도구/CDN의 자동 압축 해제로 파일 내용이나 확장자가 변하지 않도록 확인.
- index.html/release.json은 매번 재검증(no-cache). hash Build 파일은 장기 캐시 가능.
  기존 서비스워커가 도메인 전체를 제어한다면 /nyan-link/ 캐시/경로 간섭도 점검.

4. 업데이트·복구
최초 배포 전 기존 nyan-link/가 있으면 전체 백업.
새 hash Build 파일과 기타 리소스를 먼저 업로드한 뒤 index.html을 마지막에 교체.
업로드 중 이전 index가 참조하는 파일을 바로 삭제하지 말 것.
배포 도구가 디렉터리 원자 교체를 지원하면 전체 새 폴더를 준비하고 교체 가능.
최종 주소는 /nyan-link/로 유지. URL 디렉터리를 버전별로 바꾸면 브라우저 저장 위치도 달라짐.
문제 시 이전 index와 해당 파일 묶음을 함께 복원. 사용자 브라우저 저장은 삭제하지 말 것.
파일만 교체한 경우 CDN의 index/release 캐시를 갱신하고 일반 새로고침으로 새 빌드 확인.

5. 로컬 재현
프로젝트 루트에서:
  python3 Tools/serve_web.py
브라우저: http://127.0.0.1:8080/nyan-link/
HTML을 더블클릭하는 file:// 방식은 지원하지 않음.
서버는 프로젝트 소스가 아닌 Builds/Web만 127.0.0.1에 제공. 종료는 Ctrl+C.

빌드:
정확한 Unity 버전의 Web Build Support 필요. 같은 프로젝트 Unity는1개만 실행.
권장: bash Tools/build_web.sh
이 스크립트는 빌드/패키징 및 Unity가 자동 변경하는 프로젝트/클라우드 설정 복원을 수행.
NYANLINK_UNITY로 Unity 실행 파일 경로를 지정할 수 있음. 원래 설정의 백업은
Builds/WebToolchain/settings.*/에 보존. 동시에 프로젝트 설정을 편집하지 말 것.
Unity 메뉴 Nyan Link > Build Web Test 또는 아래 직접 명령도 가능하나 Unity의 부수적인
설정 직렬화는 직접 검토해야 함(메뉴 빌드는 패키징을 별도 실행).
  Unity -batchmode -quit -projectPath <프로젝트 절대경로> -buildTarget WebGL
        -executeMethod NyanLinkWebBuild.Build -logFile <새 로그 절대경로>
Unity 실행 파일은 설치 버전의 Unity.app/Contents/MacOS/Unity.
NYANLINK_WEB_PATH 기본 Builds/Web/nyan-link,
NYANLINK_WEB_OUTPUT 기본 output/playtests/2026-11-16-web. 다음 검사는 새 출력 폴더 지정.
  python3 Tools/package_web.py
도구는 원격 업로드를 하지 않으며 실패한 빌드에서는 패키징하지 말 것.

현재 Mac 환경 주의:
내장 디스크 공간 부족으로 공식 Web 모듈을 Builds/WebToolchain/WebGLSupport에 추출하고
/Applications/Unity/Hub/Editor/6000.3.14f1/PlaybackEngines/WebGLSupport로 연결.
공식 pkg MD5 검증 일치: /2GVk1bKt0jCxnROAT9igw==.
Builds/WebToolchain은 배포 파일이 아니며 커밋/업로드 대상이 아님.
이 모듈 경로를 사용하는 동안 해당 폴더를 지우지 말 것. 다른 컴퓨터는 Hub에서 정상 설치 가능.
긴 TMPDIR은 macOS 소켓104자 제한을 넘으므로 임시 파일은 짧은 경로 사용.
이번 검사는 /tmp/nyanlink-web-tmp → Builds/WebToolchain/tmp 연결,
TMPDIR=/tmp/nyanlink-web-tmp, BEE_CACHE_DIRECTORY=<프로젝트>/Builds/WebToolchain/bee-cache 사용.
