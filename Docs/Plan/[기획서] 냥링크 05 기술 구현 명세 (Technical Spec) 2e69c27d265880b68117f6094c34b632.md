# [기획서] 냥링크: 05. 기술 구현 명세 (Technical Spec)

## 1. 개발 환경 및 필수 패키지 (Environment)

### 1.1. 엔진 및 파이프라인

- **Engine**: Unity 6.0+ (LTS 권장)
- **Render Pipeline**: **URP (Universal Render Pipeline) 2D**
    - *설정*: 2D Renderer Data 사용, Post-processing 활성화.
- **Version Control**: Git (GitHub/GitLab)

### 1.2. 외부 패키지 (External Packages)

- **NineMood.LocalDB**:
    - 용도: 밸런싱 데이터(Spreadsheet) -> ScriptableObject 변환.
    - 적용 대상: 캐릭터 스탯, 장비 데이터, 전리품 테이블, 레벨업 비용 등.
- **NineMood.Services**:
    - 용도: 모바일 서비스 통합.
    - 모듈: **Ads** (보상형 광고), **Analytics** (유저 로그), **Crashlytics** (오류 보고).
- **Input System Package**: 터치 및 제스처 입력 처리.
- **Newtonsoft.Json**: 데이터 직렬화/역직렬화 (저장 시스템).

## 2. 데이터 구조 (Data Structures)

### 2.1. 퍼즐 시스템 데이터 (Puzzle Logic)

### A. 좌표계 (Hex Coordinates)

- **Offset Coordinate**: Unity Tilemap의 `Vector3Int`. 렌더링용.
- **Cube Coordinate**: 게임 로직용 `(q, r, s)`. `s`는 `q-r`로 계산.
    - *필수 메서드*: `OffsetToCube()`, `CubeToOffset()`, `GetDistance()`, `GetLine()`(직선 판정).
- **좌표 컨벤션 (odd-q 오프셋)**:
    - 홀수 열(`col % 2 == 1`): 짝수 열 대비 아래로 0.5칸 시프트.
    - 홀수 열 7행, 짝수 열 6행 배치 (Doc02 §1.1 기준).
    - Unity Grid 설정: Hexagonal / Stagger Axis Y / Stagger Amount 0.5.
    - 좌표 원점: 그리드 좌하단 (0, 0). 화면 중앙 정렬은 카메라 오프셋으로 처리.

### B. 타일 인스턴스 (Tile Instance)

C#

`[System.Serializable]
public class TileInstance {
    public string uniqueId;        // 풀링 식별자
    public TileColor color;        // Red, Blue, Yellow...
    public ItemEffectType itemType;// None, Recovery, TimeFreeze...
    public HexCoordinates coords;  // Cube 좌표
    public bool isMatched;         // 현재 체인에 포함 여부
}`

### C. 벌집형 그리드 생성 (Honeycomb Generation)

Doc 02의 교차 배치를 구현하기 위한 로직입니다.

- **Algorithm**:
    - `MapWidth`, `MapHeight` 설정값 로드.
    - **odd-q 컨벤션 적용**: `col % 2 == 1`(홀수 열)일 때 행 수 7개, `col % 2 == 0`(짝수 열)일 때 행 수 6개. 홀수 열은 Y축 기준 0.5칸 아래로 시프트.
    - **Masking**: `GridShapeData`를 통해 특정 좌표의 생성을 막아 스테이지 모양 결정.

## 3. 핵심 로직 구현 명세 (Core Logic Specs)

### 3.1. 게임 루프 및 상태 머신 (Game Loop)

- **Manager**: `GameManager` (Singleton).
- **State Machine**:
    - `Briefing`: 스테이지 진입 연출.
    - `RunnerPhase`: 장애물 등장 및 러너 진행 (거리 증가).
    - `BossPhase`: 러너 정지, 보스 패턴 UI 활성화, 전투 루프.
    - `Result`: 승리(전리품 팝업) / 패배(이어하기).

### 3.2. 입력 시스템 (Input Action Map)

- **Action Map 1: Puzzle (Touch)**
    - `Press`: 터치 시작 (타일 선택).
    - `Drag`: 드래그 (타일 연결). `PointerMove` 이벤트에서 레이캐스트로 타일 감지.
    - `Release`: 터치 종료 (매칭 판정 및 액션 실행).
- **Action Map 2: UI**
    - 기본 UI 클릭 처리.

### 3.3. 스태미나 및 점수 계산

`NineMood.LocalDB`로 로드된 계수를 사용합니다.

- `CalculateScore(count, chainBonus)`: `Spreadsheet`의 계수 참조.
- `ApplyDamage(value)`: 아래 순서로 처리.
    1. `isInvincible == true` → `damage = 0` 반환 (Cyan Invincible 효과, 1회 소비 후 해제).
    2. `isBlocking == true` → `damage = 0`, `isBlocking` 플래그 해제 후 반환 (Yellow Block 성공, 1회 소비).
    3. 이외 → `stamina -= value` 전량 차감.
- `CalculateGroggyDamage(matchedCount, comboMultiplier)`: `(matchedCount × ScoreBase) × Pow(2, comboMultiplier) × GroggyDamageFactor`. 계수는 BalanceData에서 로드.
- `CalculateAttackDamage(baseValue, powerUpBonus, isGroggy)`: `baseValue × (isGroggy ? GroggyDamageMultiplier : 1.0) × (1 + powerUpBonus)`. PowerUpBonus는 소비 후 0으로 초기화.

## 4. UI 시스템 구조 (UI Toolkit)

### 4.1. 아키텍처

- **MonoBehaviour**: `UIManager`가 `UIDocument`를 참조.

- **TopView.uss**: Pixel Font, Retro Colors 적용.

## 5. 최적화 및 저장 (Optimization & Save)

### 5.1. 최적화 (Unity 6 Optimized)

- **Object Pooling**: `UnityEngine.Pool` 사용.
    - 대상: 타일(Tile), 이펙트(VFX), 투사체, 대미지 폰트.
- **Sprite Atlas**: UI 이미지와 인게임 타일 스프라이트를 각각 아틀라스로 묶어 배칭(Batching) 최적화.
- **Async/Await**: `Awaitable`을 사용하여 코루틴 대체 (보스 패턴 시퀀스, UI 팝업 대기 등).

### 5.2. 데이터 저장 (Serialization)

- **저장 포맷**: JSON (암호화 적용 권장).
- **저장 트리거 (인게임 체크포인트)**:
    - 장애물 클리어 직후 (성공/실패 무관).
    - 보스 패턴 종료 직후.
    - *매 타일 매칭 단위 저장 없음* (I/O 부담 방지).
- **저장 항목**:
    - 유저 재화 (Coin).
    - 보유 캐릭터 및 성장 정보.
    - 보유 장비 리스트 (Instance ID, 옵션 정보).
    - 스테이지 클리어 정보 (Stars).
    - **인게임 진행 상태** (이어하기용): 현재 스테이지 ID, 완료된 장애물 인덱스, 보스 현재 HP, 현재 Phase 인덱스, 현재 스태미나.
